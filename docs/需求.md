# Wellora（知安）需求

生效日期：2026-10-30（Asia/Shanghai）。本文依据用户确认的方案、PRD V1.1、前端设计 V1.1 和交接文档整理。它定义待开发行为，不表示功能已经实现；当前 Android 已完成 S01 标准模式首页代表页，其余业务仍待实现。

## 1. 产品目标与首版边界

解决健康资料分散、报告难理解、历次指标难对比、就诊准备不足和用药容易遗忘的问题。默认标准模式，兼顾可主动切换的长辈模式；产品不是老人专用应用，也不是只有聊天入口的机器人。

- 首阶段面向中国大陆、不超过 20 个成年账号，普通话；未成年人监护授权不纳入当前试用。
- 首版规划 F01–F12，分阶段验收。报告对比和科室推荐保留在首版计划内。
- 用户名＋密码注册登录，首版不发送验证码、不提供邮件找回；家属通过邀请和双方确认绑定。
- 本人和家属使用同一个 App。家属权限与显示模式独立；医生只接收用户导出的摘要，无医生端。
- 不自动确诊、开方、停换药、调量或决定补服；不接挂号、支付、硬件、医院导航，不新增管理后台。
- 药品知识、临床风险规则和医学审核暂无资源。相关自动判断未完成前必须标记“未完成校验／能力未启用”，不计入真实可用功能验收。
- 联网完成正式保存、AI 分析和家庭协助；本地仅保留受保护的本人草稿、必要缓存、提醒计划，不做完整离线编辑及自动合并。

核心流程：选择本人或授权档案 → 拍照／上传／语音录入 → 校对确认 → 档案归档 → 解读与报告对比 → 科室参考 → 就诊摘要 → 复诊和用药记录。紧急入口不依赖上传完成；自动分级仍受医学审核门槛约束。

## 3. 数据、权限和失败边界

- 报告保留原值、单位、参考范围、日期、原异常标记和人工确认信息；来源缺失不能补成正常。未知可比性不能强行换算。
- 版本与授权在服务端校验。多人同时修改时提示冲突，查看新版本后重提，不能静默覆盖。
- 录音点一次开始、再点结束；发送前可改转写。播放主动触发，可暂停；系统 TTS 不可用时保留文字并说明。
- 当前自动医学风险判断不对外启用；不返回“低风险”冒充评估。紧急帮助提供简短就医提示和用户触发的地区确认后拨号入口，不自动呼叫。
- 撤销授权后清除可访问缓存；离线设备需联网获知撤销，不承诺远程擦除下载文件。
- 删除包含数据库正文、OSS 原图／派生文件、导出物、任务载荷和本系统缓存；第三方留存政策须在真实试用前核实。
- 用户下载的 PDF、备份属于用户持有副本，无法远程收回；导出前告知保存责任。系统备份独立加密并限恢复权限。
